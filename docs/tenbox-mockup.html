      How Tenbox is built

      Tenbox wraps Claude Code. Claude Code does the agent work. Tenbox decides where each agent runs, what it sees, what it cannot do, and how you watch it. Example data on this page is invented for the mockup.

      tenbox.yaml

      project: my-app
compose: tenbox/compose.yaml
services:
  panel:  { kind: web,      port: 5173 }
  api:    { kind: api,      port: 4000, openapi: /openapi.json }
  db:     { kind: postgres, seed: pnpm db:seed }
  stripe: { kind: fake,     spec: fakes/stripe.openapi.yaml }
  mails:  { kind: queue }
locked: [openapi.yaml, e2e/]
checks:
  api: pnpm test:api      # every task
  ui:  on-fe-change       # Playwright MCP + screenshots
budget: { max_agents: 6, max_depth: 2, stop_spawn_at_limit: 85 }

      The panel knows only service kinds and hook events. A new project needs only this file.

      Rules agents cannot break

      1. Budget: max agents, max depth, no spawn near the subscription limit.
      2. Merge needs a reviewer that did not edit the code.
      3. Spec changes and merges need your answer.
      4. Locked paths are blocked by a PreToolUse hook.
      5. Product, contract and risk questions always reach you.
